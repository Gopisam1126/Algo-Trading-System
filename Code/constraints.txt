# Resolved dependency versions — the lockfile for reproducible builds.
#
# WHY THIS EXISTS
#
# pyproject.toml declares FLOORS (`>=`), which is right for a library and wrong
# for a deployed artifact. Without this file, CI, the Docker build and a
# developer's laptop each resolve dependencies independently, minutes apart, and
# can get different versions with no code change. That means:
#
#   - the image is not the thing CI tested;
#   - a build is not reproducible, so "it worked last month" is unverifiable;
#   - a breaking or compromised upstream release lands automatically, on a
#     system that holds broker credentials and will move real capital.
#
# This is the same lesson the pinned `ruff==` / `mypy==` lines in
# pyproject.toml record, applied to the runtime dependencies rather than only
# to the linters.
#
# HOW IT IS GENERATED
#
# Inside the SAME image the Dockerfile builds from, because a freeze taken on
# Windows pins the wrong wheels — it would omit `uvloop` (marked
# `sys_platform != 'win32'`) and add Windows-only packages that do not exist on
# Linux:
#
#   docker run --rm -v "$(pwd)":/w -w /w python:3.11-slim-bookworm bash -c '
#     apt-get update -qq && apt-get install -y -qq gcc python3-dev
#     python -m venv /tmp/v && /tmp/v/bin/pip install -q ".[dev]"
#     /tmp/v/bin/pip freeze | grep -v "^algotrader" > /w/constraints.txt'
#
# Then re-add this header.
#
# HOW IT IS USED
#
# `pip install -c constraints.txt ...`. Constraints bound the version of
# anything that gets installed but do not themselves install anything, so one
# file serves both `.[dev]` in CI and the runtime-only install in the image.
#
# UPDATING
#
# Regenerate deliberately, as its own commit, so the diff shows which
# dependencies moved. Re-run `pip-audit` afterwards.
